# fde-rag-quote · 询价单自动报价（RAG 版）

在 [FDE-demo](https://github.com/Goat723-hub/FDE-demo) 的主体框架上，加了两处检索：

1. **相似历史报价检索** —— 给每一行报价算一个参考区间
2. **工艺规则库** —— 把自然语言规则编译成确定性校验

一句话概括这次改动的边界：

> **RAG 只提供旁证，不参与计算。**

---

## 为什么不是「把历史报价塞进 prompt」

原项目的核心约束是：

> LLM 有提议权，人有批准权，机器只有执行权。

报价 = `重量 × 材料单价 + 工序费 + 开机费 × 急单系数`，全部在 `pricing.py` 里算。
如果让模型「参考历史报价综合给出价格」，这条约束当场失效，而且结果不再可复现。

所以本项目里，检索结果走的是**两条独立的道**：

```
                    ┌──────────────┐
  图片 ──► LLM 识别 ─┤ 结构化字段   │
                    └──────┬───────┘
                           ▼
                    ┌──────────────┐        ┌─────────────────┐
                    │ pricing.py   │◄───────┤ ① 相似历史检索   │
                    │ 确定性计价   │        │   只读，产出区间 │
                    └──────┬───────┘        └─────────────────┘
                           ▼
                    ┌──────────────┐        ┌─────────────────┐
                    │ rules.py     │◄───────┤ ② 工艺规则库     │
                    │ 确定性校验   │        │   编译为条件对象 │
                    └──────┬───────┘        └─────────────────┘
                           ▼
                    ┌──────────────┐
                    │ llm.py 摘要  │  只念 Python 算好的数字
                    └──────────────┘
```

模型拿到的仍然是 `facts` —— 一堆已经定死的数字。它多出来的工作只是解释一句「为什么偏离参考价」。

---

## 三个关键决策

### ① 检索不是纯向量，而是「门控 + 三维混合」

| 维度 | 算法 | 权重 |
|---|---|---|
| 材质 | **硬门控**，归一后必须相同 | 不过就出局 |
| 零件名 | 字符 n-gram 余弦 | 0.5 |
| 工艺重合 | Jaccard | 0.3 |
| 重量接近 | `exp(-|ln(w₁/w₂)|)` | 0.2 |

为什么材质是门控而不是一维打分：304 和 Q235 的单价差 4 倍，
它们的相似度不该是「低」，而是**不可比**。

为什么默认不用 sentence-transformers：首次要下 100MB 权重。
`rag/embed.py` 是可插拔接口，设 `RAG_EMBEDDER=st` 就切真语义模型，调用方不用改。

### ② 阈值是跑出来的，不是拍的

向量检索有个毛病：库里只有 50 条时，你问一个毫不相干的零件，它照样返回 50 条，
永远不会告诉你「没有」。

所以 `RAG_MIN_SCORE` 由 `scripts/eval_retrieval.py` 用 leave-one-out 实测标定。
**换数据或换 embedder 后必须重跑**，不能沿用。

### ③ 规则由代码执行，模型不参与判断

`rules.md` 是人写的自然语言，但结构固定，能被解析成条件对象：

```markdown
## R01 304 不锈钢不建议镀锌
- when: material = 304不锈钢
- and: process contains 镀锌
- level: warn
- message: 304 不锈钢镀锌附着力差，批量易起皮，建议改为电解抛光或直接钝化。
```

解析之后就是普通的 Python 比较。同样的输入永远得到同样的输出。

RAG 在这里唯一的用途是**规则多了以后做预筛**。当前 11 条规则直接全量跑；
`select_rules()` 的预筛结果必须和全量扫描完全一致 —— 由 `eval_rules.py` 保证。

## 实测数字

全部可复现，命令见下文。

| 指标 | 结果 |
|---|---|
| 检索 recall@1 / @3 / @5 | **1.000 / 1.000 / 1.000**（50 条 LOO） |
| 正样本分数（同一零件） | p5=0.920, p50=0.971 |
| 负样本分数（不同零件） | p5=0.287, p50=0.395, p95=0.480 |
| 标定阈值 | **0.51**（precision 1.000 / recall 1.000） |
| 规则拦截率 | **1.000**（13/13） |
| 规则误杀 | **0** |
| 预筛 vs 全量 | **完全一致** |
| 跨进程可复现 | **是**（3 次子进程 sha256 相同） |

> 这些数字来自**合成数据**（50 条、10 种零件）。真实场景下 recall 不会这么漂亮，
> 上生产前必须用自己的历史报价重跑。

## 运行

```bash
pip install -r requirements.txt

# 三个评测，30 秒内跑完
python scripts/eval_retrieval.py
python scripts/eval_rules.py
python scripts/eval_reproducibility.py

# 重新生成历史数据（可选）
python scripts/make_history.py

# 起后端
uvicorn backend.main:app --reload --port 8000
```

新增接口：

| 接口 | 作用 |
|---|---|
| `GET /api/rules` | 规则库（给人看的，确认系统在按什么执行） |
| `GET /api/rag/status` | 当前 embedder、索引条数、阈值 |

`POST /api/quote` 的返回里新增了 `violations`、`blocked`，
以及每行的 `reference`（p25/p50/p75）和 `deviation_pct`。

`POST /api/pdf` 在存在 `level: error` 的违规时**直接返回 400**，不出报价单。

## 已知局限

1. **数据是合成的。** 50 条历史报价由 `make_history.py` 生成，
   同一零件的 5 条记录共享同一个工艺组合，所以检索任务偏简单。
2. **字符 n-gram 不是语义模型。** 它能认出「法兰盘/法兰」，认不出「法兰盘/联结盘」。
   换 `RAG_EMBEDDER=st` 能解决，但评测数字要重跑。
3. **规则只有 11 条。** 预筛优化的收益还没体现，目前的价值是接口先留好。
4. **`quotes_log.json` 不用于检索。** 新报价归档了，但不进索引 ——
   否则同一个进程跑两次评测，结果会互相污染。
